# Libre Coffee Aarchive

React + TypeScript + Vite 기반의 실행 가능한 커피 산지 인텔리전스 아카이브 프로토타입입니다. 밝은 회백색 배경, 반투명 카드, 큰 타이포, 24–28px 라운드, 절제된 그림자를 적용했습니다. 산지 일러스트는 프로젝트에 포함된 SVG이며 사진의 진위를 암시하지 않습니다.

**기본 화면은 기존 GitHub Pages 아카이브의 실제 보관 데이터 2,015개를 표시합니다.** 원문, 날짜, 원본 Instagram 링크, 보관 이미지를 그대로 연결합니다. 기존 파일의 마지막 기록은 2026-01-28이며 추가 파일에 2026-10-03까지 공개 목록 71건을 보완해 총 2,086건을 표시합니다. 원본 링크가 현재도 열리는지는 별도로 확인해야 합니다. 기존 카테고리와 요약은 새 모델로 분석하거나 사실 검증하지 않았습니다. 일반 카테고리 및 복합 국가 그룹은 국가로 단정하지 않고 ‘국가 미분류’로 보존합니다. 기존 농장 이름 5개를 연결하고, 검증된 생산자 분류가 없으므로 생산자를 만들어 넣지 않습니다.

현재 위치는 확정하지 않습니다. 최신 공개 기록과 주간 수집 상태를 표시합니다. 매주 월요일 오전 9시(한국 시간) Codex 로컬 브라우저로 수집하며 로그인 문제는 이 채팅에 알립니다. 실행에는 컴퓨터·Codex·브라우저 로그인이 필요합니다. 자세한 운영 절차는 [WEEKLY_COLLECTION.md](WEEKLY_COLLECTION.md)를 참고하세요. 외부 최신 자료는 아직 연결하지 않았습니다. `?demo=1`을 주소 뒤에 붙이면 별도의 가상 데이터 시연 모드를 열 수 있습니다. 가상 데이터는 실제 데이터와 섞이지 않습니다. 이 프로젝트는 커피리브레의 공식 서비스가 아닙니다.

## 기존 GitHub Pages 교체

대상: `https://gachicoffee.github.io/Archive/` / `Gachicoffee/Archive` 저장소.

- 기존 `main` 루트 Pages 배포를 유지합니다. 루트 `index.html`와 `assets/`가 새 앱의 빌드 결과입니다.
- 원본 `archive_data.json`은 변경 없이 그대로 보존합니다. 앱은 이 파일을 읽고 기존 구조를 변환하는 `src/data/legacy.ts`를 사용합니다.
- 기존 화면은 `legacy/index.html`에 보존합니다. 복구 시 Git 이력 또는 이 화면을 사용할 수 있습니다.
- 저장소의 개발 소스는 `app/`에 있습니다. `cd app`, `npm ci`, `npm run build:pages`로 루트 배포 파일을 갱신한 뒤 커밋/푸시합니다.
- ZIP 소스는 프로젝트 자체가 최상위입니다. 일반 `npm run build`는 `dist/`에 만들며 GitHub에 배포할 파일은 이 디렉터리의 내용입니다.
- `/Archive/`의 정적 파일을 상대 경로로 참조하고 화면 이동은 클라이언트 상태를 사용하므로 각 메뉴에 별도 서버 rewrite는 필요하지 않습니다.

아래의 화면 설명과 아키텍처 중 ‘예시 데이터’ 부분은 `?demo=1` 시연 모드에 해당합니다. 기본 모드는 실제 보관 데이터와 과거 요약을 사용합니다. 초기 3건은 AI 요약이고 추가 68건은 원문 발췌입니다. embedding·자동 브리핑 생성은 미연결입니다.

## 실행

Node.js 22 이상과 npm을 권장합니다. 터미널에서 프로젝트 폴더로 이동한 뒤:

```sh
npm ci
npm run dev
```

표시되는 로컬 주소(기본 `http://127.0.0.1:5173`)를 브라우저에서 엽니다.

```sh
npm run build
npm run preview
npm test
```

`build`는 TypeScript 검사와 배포 파일 생성을 수행합니다. 빌드 결과는 `dist/`에 생성됩니다. ZIP의 `preview/`에는 검증한 정적 빌드를 별도로 동봉했습니다. ES module을 사용하므로 HTML 파일을 더블클릭하는 대신 로컬 HTTP 서버로 열어야 합니다. 예: ZIP을 푼 폴더에서 `python -m http.server 8080 --directory preview` 실행 후 `http://127.0.0.1:8080` 접속. Node 개발 서버는 소스 수정에 적합합니다.

글꼴은 Google Fonts를 사용하고 네트워크가 없으면 시스템 글꼴로 대체됩니다. 지도와 일러스트는 외부 이미지 서비스에 의존하지 않습니다. 외부 기관 및 Instagram 링크는 사용자가 클릭할 때 이동합니다.

## 구현한 경험

- **Home**: 방문 지역 형식의 요약, 이번 주 신규 기록, 태그 빈도, 실제 예시 데이터에서 계산한 신규 농장·생산자, 최근 소식, 외부 정보 카드.
- **Explore**: 국가·농장·생산자별 통합 페이지와 국가/주제 필터.
- **Search**: 자유 문장 입력, 한국어·영어 동의어 확장, 관련 검색어, 관련도순 카드, 같은 주제의 연도순 기록.
- **Stories**: 농장·생산자의 이야기를 연도별로 통합하고 근거 버튼으로 가상 캡션 확인.
- **Timeline**: 2018–2026 타임머신. 선택한 연도까지의 기록만 표시. 통합 이야기에도 같은 연도 설정 적용.
- **Map**: 개략적인 국가 지도, 클릭 가능한 국가 지점과 통합 기록. 좌표나 국경의 정확성을 위한 지도는 아님.
- **Weekly**: 고정 데모 기간(2026-09-28~2026-10-03)의 브리핑과 학습 카드, 근거 연결.
- **Archive**: 브라우저별 북마크, 예시 JSON 내보내기, 4K Stogram import placeholder.
- AI 정리(녹색), 원문 형식(베이지), 외부자료(청회색)를 색상·아이콘·텍스트로 구분.
- 데스크톱/태블릿/모바일 레이아웃, 키보드 포커스 표시, 지도 키보드 선택, 모달 Escape 닫기.

임베딩과 별도 LLM API는 연결하지 않았습니다. 실제 수집·예약·문제 알림은 로컬 Codex 자동화로 연결했습니다. 검색의 여러 조건은 엄격한 AND 필터가 아니라 키워드 관련도 합산으로 동작합니다. 자연어 검색 UI와 검색 알고리즘을 혼동하지 않도록 검색 페이지에 이를 표시합니다. 농장별 연도 요약은 해당 연도의 예시 요약들을 모아 보여주는 방식입니다.

외부자료 카드는 WMO/OVSICORI를 **참고 기관 링크**로 제공할 뿐 최신 기사나 관측 결과를 인용하지 않습니다. 화산 폭발이나 농장 피해를 확인했다고 주장하지 않으며 발행일·검증일을 미연결로 표시합니다.

## 데이터 계층과 확장 지점

```text
src/
  data/types.ts       Post, Entity, ExternalIssue, ArchiveProvider, Collector, ImportAdapter
  data/mock.ts        가상 게시물 12개 / 농장 4곳 / 생산자 4명 / 참고기관 카드 2개
  data/provider.ts    provider factory와 로컬 동의어 검색
  App.tsx            화면과 탐색 동작
  styles.css         반응형 디자인
tests/data.test.ts   검색, 참조 정합성, 주간 집계, mock 격리 검사
```

`getArchiveProvider()`만 API provider로 교체하면 UI의 snapshot/search 호출을 유지할 수 있습니다. `Collector`는 페이지 cursor와 다음 cursor를 반환하는 교체 가능한 수집기 계약입니다. `ImportAdapter`는 실제 내보내기 샘플을 읽고 공통 Post로 변환하는 계약입니다. 현재 import 화면은 파일명만 확인하고 업로드나 파싱을 하지 않습니다.

현재의 `Post`는 최소 프로토타입 스키마입니다. 운영에서는 아래와 같이 분리하는 것을 권장합니다.

```text
raw_posts       플랫폼 ID, 작성일, 수집일, 원본 URL, 변경 버전, 불변 원문
media_assets    원본 경로, 허용된 보관 위치, 파일 hash, 권한 정보
entities        국가/지역/농장/생산자, 별칭, 정규화된 이름, 검증 상태
post_entities   관계 유형, 확신도, 원문 span/offset, 검토 여부
claims          관찰/인용/추론 구분, 모델 버전, 근거 post ID, 근거 span
chunks          검색 단위, embedding, post ID, 분류 메타데이터
external_items  기사/발표 URL, 출처, 발표일, 확인일, 영향 지역, 근거 문장
briefings       기간, 사용한 근거 ID, 생성 모델, 검토 상태, 발행 상태
```

## 향후 수집 → 검색 → 브리핑 아키텍처

```text
교체 가능한 Collector / 4K ImportAdapter
  → 원문과 미디어 저장 → URL·날짜 검증 → 플랫폼 ID/hash 중복 제거
  → 작업 큐 → 언어/엔티티/태그 추출 → 별칭 정규화와 사람 검토
  → chunk 분할 + embedding → PostgreSQL + pgvector
  → API ArchiveProvider → React UI

사용자 질문 → 국가/기간/주제 추출 → 키워드 + 벡터 검색
  → 재정렬 → 근거 span 기반 답변 → 게시물별 출처 링크

허용된 외부 피드 → 발표일·지역·사실 검증 → 외부자료 별도 저장
  → 농장/지역 기록과 관계 연결 (관찰과 영향 추론을 구분)

주간 scheduler → 지난 성공 cursor 이후 변경분
  → 지역별 브리핑 → 근거 검사 → 검토/발행 → 선택한 알림 채널
```

1. **Instagram 수집**: 원본 소유자의 협조·제공 데이터 또는 사용 가능한 공식 접근 경로를 먼저 검토합니다. 공개 계정 전체 수집을 공식 API에서 언제나 제공한다고 가정하지 않습니다. 적용 시점에 권한·정책·기능을 확인하고 collector를 교체합니다. 로그인 우회 코드나 실제 계정 인증정보는 포함하지 않습니다.
2. **4K Stogram import**: 내보내기 버전별 JSON/CSV/캡션 파일 및 미디어 폴더 샘플을 확인하고 매핑합니다. 가져오기 전 미리보기에서 날짜·시간대(Asia/Seoul 표시), URL, 중복, 누락 캡션을 확인합니다. ID가 없으면 hash 기반 내부 ID를 만들되 실제 원본 URL을 추측하지 않습니다. 사진 EXIF나 파일 수정일을 게시일로 단정하지 않습니다.
3. **엔티티 통합**: 동명이인/유사 농장명/철자 변형을 별칭 테이블과 사람이 검토합니다. 농장과 생산자는 다대다 관계로 분리합니다. 품종·가공·기후·토양/고도·병충해·가격·문화·노동·관계·방문 등 다중 태그를 부여합니다.
4. **의미 검색**: 서버에서 embeddings를 만들고 pgvector와 텍스트 검색을 결합합니다. API key는 서버 환경 변수에만 저장합니다. 답변은 검색 근거와 범위 안에서 생성하며 근거 없는 농장 피해나 현재 위치는 생성하지 않습니다.
5. **현재 위치 추정**: 게시일과 방문일을 구분하고 직접 방문/과거 회상/원격 대화를 분류합니다. 근거 날짜·확신도·유효 기간을 표시하고 오래된 게시물만 있으면 ‘현재 위치 미확인’으로 전환합니다.
6. **외부 최신 자료**: 발표 시각과 사건 시각을 별도로 저장합니다. 국가 전체의 사건을 특정 농장 피해로 자동 단정하지 않습니다. 영향 추론은 지리·시점 근거와 함께 별도 표시합니다.
7. **주간 자동화**: idempotent 작업, 재시도, dead-letter 큐, cursor 저장, 변경 추적을 적용합니다. 브리핑 내용이 없으면 알림을 생략하고, 신규 기록 또는 중요한 검토가 있을 때만 발행합니다.

배포 전에 인증·백업·접근 권한·자료 사용 범위·원문 수정/삭제 동기화, 실제 출처 검증과 접근성 검사를 확장하세요. 북마크는 현재 localStorage만 사용하며 기기 간 동기화는 하지 않습니다.


## 2026-10-03 농장 재점검

기존 5개 고정 목록을 확장했습니다. 전체 2,086개 캡션을 스캔하고 이름 후보의 원문 문맥을 검토하여 농장 76곳과 가공소 2곳을 분리했습니다. 332개 게시물이 이름으로 연결되며 96개는 복수 농장을 언급합니다. `src/data/farm-catalog.json`에 검토된 별칭과 대표 근거가 있습니다. `farms.ts`가 전체 원문에 대해 다대다 연결을 만들고, 이름이 없는 농장·지역·인물·로트는 농장으로 생성하지 않습니다. 같은 이름의 다른 농장은 자동 합치지 않으며 검토가 필요한 명칭은 catalog.pending에 보관합니다. Stories에서 이름·국가·농장/가공소 유형으로 찾을 수 있습니다. 농장 연도 화면은 AI가 새로 통합한 전기가 아니라 해당 농장명이 나오는 원문 발췌와 모든 근거 링크입니다. 원문에 없는 국가·고도·생산자 관계를 보완하지 않았습니다. 신규 게시물은 같은 별칭으로 즉시 연결하며, 새 농장 이름은 catalog를 검토·확장한 후 다시 빌드해야 합니다.


## 2026-10-03 이름·브랜드 방향·탐색 개편

표시 이름은 요청한 철자인 **Libre Coffee Aarchive**입니다. 기존 작업 폴더와 데이터 파일 이름은 주간 수집 경로와 호환되도록 유지합니다.

가치커피 브랜드 가이드 v1.3-S의 종이 #ECE3D4, 먹 #151936, 초록 #00593B와 주황 #DE531E를 참고했습니다. 본문은 Pretendard, 영문 브랜드는 Montserrat, 숫자는 모노 계열입니다. 웹폰트 불러오기가 차단되면 시스템 서체로 대체합니다. 이 아카이브는 가치커피 공식 브랜드 사이트가 아니며, 사용자가 요청한 Apple 스타일에 맞춰 24px 카드·28px 모달·반투명·절제된 blur를 유지했습니다. 브랜드 로고를 새 이름에 변형해 사용하지 않습니다.

홈 숫자 카드는 전체 기록 목록 / 농장 목록 / 국가별 탐색 / 최근 기록 연도 목록으로 연결됩니다. Explore·Search·Timeline에서 국가, 큰 분류, 세부 주제, 게시 연도를 조합하고 최신순·오래된순·제목순·연결 농장 수로 정렬합니다. Search는 관련도순도 지원합니다. Timeline의 타임머신 연도 상한과 게시 연도 필터는 함께 적용됩니다. 기존 북마크는 그대로 보존됩니다.

### 원문 기반 추정 분류

`src/data/taxonomy.ts`가 로드된 전체 2,086개 기록과 이후 추가 기록을 동일하게 분류합니다. 7개 큰 분류와 26개 세부 주제(검토 대기 포함)를 사용합니다. 농장·생산·기후, 품종·가공·로스팅·추출·커핑·논문·철학·교육, 산업·가격·리브레 운영·행사, 카페 투어·산지 출장·여행, 동물·사람·음식·일상, 책·문화·개인 생각을 복수 주제로 연결합니다.

이는 **원문 표현과 문맥 조건을 활용한 규칙 기반 추정**이며 모든 기록을 LLM으로 정독하거나 확정 검수한 결과가 아닙니다. 기존 category와 tags를 세부 주제 판단의 원본으로 사용하지 않으며 원문·기존 분류·요약을 삭제하거나 덮어쓰지 않습니다. `topics`, `topicEvidence`, `classificationKind`를 별도로 추가하고, 원문 상세의 '주제 분류 · 추정'에서 근거를 펼칠 수 있습니다. 명확한 표현이 없는 기록은 '주제 확인 필요'로 남습니다. '#커피리브레'만 있는 글을 운영 소식으로, '이라면'을 음식으로, '동물 친구'를 사람으로 취급하지 않는 문맥 조건이 있습니다. 농장 이름 연결은 검토된 farm catalog 근거를 사용합니다.

다음 단계는 Collector → 원문 저장 → 검토된 농장 연결 → 분류 모델 adapter → 근거 인용 검증 → 사람 수정 내역 → 색인입니다. LLM classifier를 교체할 때도 동일한 topic ID와 원문 인용 구조를 유지하고, 잘못 분류된 기록의 수동 수정은 모델 결과보다 우선하도록 별도 override 저장소를 두는 것을 권합니다. 현재는 모델 호출·벡터 임베딩 비용이 발생하지 않습니다. JSON 내보내기에는 추정 주제와 근거도 포함됩니다.

## 2026-10-04 가공방식·생산자 및 메뉴 정리

중복의 원인은 Explore, Search, Timeline, Archive에 같은 전체 기록 목록이 반복되고, 농장 목록도 탐색과 이야기 메뉴에 겹쳐 있었기 때문입니다. 다음과 같이 목적을 구분했습니다.

| 메뉴 | 역할 |
| --- | --- |
| Home | 최근 소식과 숫자를 확인하고 해당 기록으로 이동 |
| Explore | 분류·국가·가공방식으로 탐색하고 전체 기록·타임라인·지도를 선택 |
| Stories | 농장·가공소 또는 생산자·파트너의 연도별 원문과 출처 |
| Weekly | 주간 신규 기록과 수집 상태 |
| Archive | 개인 북마크 및 데이터 가져오기·내보내기 |

Search는 우측 상단의 공통 입구로 유지하고 사이드바에서는 제거했습니다. 검색 결과의 중복 타임라인도 제거했습니다. 전체 기록과 타임라인은 공통 `selectRecords` 필터를 사용하며 24개씩 추가 표시합니다. 지도는 국가 단위의 개요로, 정밀 농장 좌표나 전체 기록 필터에 연동되는 지도는 아닙니다.

`src/data/connections.ts`는 원문에서 12개 가공방식의 별칭과 인용 근거를 별도 색인합니다. 현재 워시드 84개, 내추럴 121개, 허니 26개, 무산소 발효 28개, 탄산침용 11개, 펄프드 내추럴 3개, 웻 헐 4개, 효모 접종 10개, 이중·다단계 발효 3개, 삼투압 가공 2개입니다. 열충격과 코퍼먼테이션은 현재 확인된 기록이 0개입니다. 한 글에 여러 방식을 연결할 수 있으므로 합계는 고유 게시물 수가 아닙니다. 관련 단어 검색은 표기 변형을 함께 찾되 워시드를 검색하면 모든 가공방식으로 넓히지 않습니다.

이는 **언급 색인**입니다. 비교·역사·부정적인 설명에 등장한 방식도 포함되며, 농장이 그 방식을 실제 사용했다는 인증이 아닙니다. 농장 이야기의 '언급 가공방식'과 '함께 등장한 이름'은 같은 게시물에서 함께 언급된 기록을 찾습니다. 농장 소유권이나 생산자와의 관계를 자동 확정하지 않습니다.

`src/data/producer-catalog.json`에는 원문에서 역할·이름·대표 출처를 확인한 생산자와 산지 파트너 17명을 등록했습니다. 전체 인명 검수가 끝난 목록은 아닙니다. 같은 이름은 농장·지역 문맥으로 구별하고 예술가·바리스타 등 다른 인물과 합치지 않습니다. 사무엘 두 사람은 별도 페이지를 가지며, 생략된 성을 임의로 보완하지 않습니다. 국가를 표시할 때는 원문에서 확인한 활동 산지를 사용하며 국적으로 단정하지 않습니다. 인물 페이지는 원문 발췌와 근거 링크를 연도순으로 보여줍니다.

원문·날짜·사진·기존 분류는 유지하고 `processingIds`, `processingEvidence`, `producerIds`, `producerEvidence`만 파생 필드로 추가합니다. 새로운 이름과 별칭은 검토 후 카탈로그를 확장합니다. 향후 모델 추출과 벡터 검색도 이 원문 근거 구조를 유지하도록 연결하면 됩니다.

## 2026-10-04 검색 별칭과 홈 이벤트

홈의 산지 일러스트·현재 위치 placeholder·CONNECTED TOPICS·CONNECT THE DOTS·중복 농장 목록·외부자료 placeholder를 제거했습니다. 전체 기록 바로가기, 원문 기반 이벤트 카드 4개, 최근 기록 6개와 수집 상태를 표시합니다.

`src/data/events.ts`는 원문의 같은 문단에서 장소와 사건 표현이 함께 있는 기록을 찾습니다. 현재 네 유형(브라질 냉해, 니카라과 흉작, 나리뇨 가뭄, 핀카 리브레 CoE)을 지원합니다. 각 유형은 가장 최근 근거의 게시 연도를 선택하고 같은 연도의 최근 원문 최대 3개를 연결합니다. 다른 연도의 사건을 같은 시즌으로 합치지 않습니다. 모든 사건을 포괄하는 자동 뉴스 수집·LLM 분석은 아니며, 새로운 이벤트 유형은 규칙과 영향 설명을 추가해야 합니다.

카드는 게시일, 사건 신호, 영향 경로, 조건부 추론, 원문 인용, 출처, 한계·후속 확인 항목을 구분합니다. 기존 요약·분류로 사건을 만들거나 2025년 냉해를 2026년 가격 상승의 확정 원인으로 단정하지 않습니다. 주간 수집으로 같은 유형의 원문이 추가되면 별도 빌드 없이 카드 근거가 갱신됩니다. 최신 원문의 연도와 선택된 시즌만 표시하므로 과거 사건 전체 목록은 아닙니다. 사건 발생일은 게시일과 다를 수 있습니다.

홈을 산지 이벤트 / 프로세싱 실험 / 논문·연구 탭으로 구성했습니다. 프로세싱 4건(삼투압, 효모 접종, 콜드퍼먼테이션, 부산제의 실험 계획), 연구 3건(품종 유전자 지문, 세포배양 커피, 드립 눈사태 효과)을 원문 검토 후 선정했습니다. 각 카드에는 4단계 버튼과 이전·다음 탐색, 원문 모달과 외부 출처가 있습니다.
